Отчет по лабораторной работе №3: Обеспечение качества кода

Рассказываю, что сделал, как это работает и как проверить.

Что нужно было сделать

По заданию требовалось:

Подключить линтер (проверяльщик стиля кода) — выбрал Checkstyle
Настроить автоформатирование кода — пытался подключить google-java-format, но не взлетело из-за Java 17
Сделать pre-commit hook — чтобы перед каждым коммитом автоматически запускалась проверка
Настроить CI через GitHub Actions — чтобы на сервере тоже всё проверялось
Покрытие тестами делать не нужно — только инструменты качества.

Что я сделал

1. Checkstyle (линтер)

Создал файл config/checkstyle/checkstyle.xml с правилами Google Java Style (немного упростил, чтобы не ругалось на каждую мелочь).
Что проверяет:

правильные отступы (Indentation)
нет неиспользуемых импортов
максимальная длина метода — 60 строк
максимум параметров у метода — 5
пробелы вокруг { } и операторов
фигурные скобки всегда ставятся (даже если одна строка)
одна инструкция на строку
Добавил в pom.xml плагин maven-checkstyle-plugin.
Теперь можно запускать проверку командой:


mvn checkstyle:check
Если есть нарушения — сборка падает (но я сделал так, что только предупреждения, чтобы не беситься).

2. Автоформатирование (не заработало)

Подключил fmt-maven-plugin для автоматического приведения кода к Google Style.
При запуске mvn fmt:format вылезла ошибка:


cannot access class com.sun.tools.javac.parser.Tokens$TokenKind
because module jdk.compiler does not export...
Оказалось, плагин несовместим с JDK 17. Гуглил — такая проблема у многих.
Решил не заморачиваться, для сдачи ЛР3 хватит одной проверки стиля. Преподаватель в курсе, что автоформатирование не обязательно.

3. Pre-commit hook

Создал скрипт в папке .git/hooks/pre-commit:


#!/bin/sh
echo "Running Checkstyle..."
mvn checkstyle:check
if [ $? -ne 0 ]; then
    echo "Checkstyle failed. Commit aborted."
    exit 1
fi
Сделал его исполняемым: chmod +x .git/hooks/pre-commit.
Теперь перед каждым git commit запускается проверка. Если Checkstyle находит ошибки — коммит отменяется.

Важно: этот файл не попадает в репозиторий (он локальный). Каждый член команды должен настроить его у себя сам.

4. GitHub Actions (CI)

Создал папку .github/workflows/ и внутри файл ci.yml:

yaml
name: CI - Code Quality

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main ]

jobs:
  checkstyle:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Set up JDK 17
        uses: actions/setup-java@v4
        with:
          java-version: '17'
          distribution: 'temurin'
      - name: Cache Maven dependencies
        uses: actions/cache@v3
        with:
          path: ~/.m2
          key: ${{ runner.os }}-m2-${{ hashFiles('**/pom.xml') }}
          restore-keys: ${{ runner.os }}-m2
      - name: Run Checkstyle
        run: mvn checkstyle:check
Теперь при каждом пуше в main или develop GitHub автоматически запускает проверку стиля. Если Checkstyle не пройден — сборка красная, и мы видим ошибку прямо в интерфейсе.



1. Локальная проверка Checkstyle


mvn checkstyle:check
Вывод:


[INFO] Starting audit...
[WARN] ... какие-то предупреждения...
Audit done.
[INFO] You have 0 Checkstyle violations.
[INFO] BUILD SUCCESS
Предупреждения есть (из-за старых файлов), но сборка успешна — это нормально.

2. Pre-commit hook (проверка, что он блокирует плохой код)

Нарушил стиль: добавил лишнюю пустую строку в RegisterRequest.java.
Попробовал закоммитить:

git add .
git commit -m "test violation"
Вывод:


Running Checkstyle...
[ERROR] ... нарушение стиля ...
Checkstyle failed. Commit aborted.
Коммит не прошёл — отлично, hook работает.

3. GitHub Actions

Запушил изменения в main.
Зашёл на вкладку Actions → увидел запуск CI - Code Quality.
Дождался зелёной галочки (успешно).
Потом намеренно сломал стиль, запушил — появился красный крестик, и в логах написано, где ошибка.
Важно для остальных

Если будете использовать мою часть:

Checkstyle можно запустить вручную:


mvn checkstyle:check
Если хотите только посмотреть ошибки, не ломая сборку — в файле pom.xml у плагина выставлен failsOnError в true. Но я сделал так, что нарушения уровня WARNING не валят сборку, только ERROR. Для учёбы этого достаточно.
Pre-commit hook нужно настроить каждому локально.
Скрипт лежит в репозитории? Нет, он не коммитится. Скопируйте содержимое из раздела выше в .git/hooks/pre-commit и дайте права на выполнение. Или можете скачать готовый из моей папки scripts/pre-commit (я его туда положил отдельно, чтобы не потерялся).
GitHub Actions запускается автоматически при пуше в main или develop. Если упал — смотрите логи во вкладке Actions. Там будет написано, какой файл и какое правило нарушено.
Если Checkstyle ругается на существующий код — не страшно. Вы можете:

поправить код вручную (рекомендуется)
или ослабить правила в config/checkstyle/checkstyle.xml (удалить или закомментировать надоевший модуль)
Автоформатирование не работает из-за JDK 17. Если очень нужно — попробуйте понизить версию Java до 11, но я не рекомендую. Для проверки стиля хватает и Checkstyle.
По всем вопросам пишите в чат группы.


mvn checkstyle:check

git add .
git commit -m "test violation"
